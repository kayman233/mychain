# Введение vs Заключение в академических статьях

## 📚 Фундаментальная разница

---

## ВВЕДЕНИЕ (Introduction)

### 🎯 Цель: МОТИВИРОВАТЬ и ОБОСНОВАТЬ

**Вопросы, на которые отвечает:**
1. **Какая проблема?** (Problem Statement)
2. **Почему это важно?** (Motivation)
3. **Что сделали другие?** (Gap in Knowledge)
4. **Что МЫ ПРЕДЛАГАЕМ сделать?** (Our Approach)
5. **В чём наш ВКЛАД?** (Contribution)

### 📝 Структура:
```
Контекст → Проблема → Существующие подходы (их недостатки) 
→ Наш подход → Вклад (что нового)
```

### ⏰ Временная перспектива:
- **Настоящее время:** описание проблемы ("существует проблема...")
- **Будущее время:** что мы ПРЕДЛАГАЕМ ("в данной работе разработана...")
- **Акцент на ПЛАНЕ:** что мы СОБИРАЕМСЯ показать

### 🔑 Ключевые слова:
- "предложена", "разработана", "формализована"
- "цель данной работы"
- "вклад работы"
- "в данной работе"

### ❌ Чего НЕТ:
- Конкретных результатов (числа, измерения)
- Выводов о том, что получилось
- Сравнения достигнутых результатов
- Рефлексии о значимости работы

---

## ЗАКЛЮЧЕНИЕ (Conclusion)

### 🎯 Цель: ОБОБЩИТЬ и ПОКАЗАТЬ ЗНАЧИМОСТЬ

**Вопросы, на которые отвечает:**
1. **Что МЫ СДЕЛАЛИ?** (Summary)
2. **Какие РЕЗУЛЬТАТЫ получены?** (Results)
3. **Чем это ЛУЧШЕ аналогов?** (Comparison)
4. **Почему это ВАЖНО?** (Significance)
5. **Что ДАЛЬШЕ?** (Future Work - кратко!)

### 📝 Структура:
```
Краткое резюме → Конкретные результаты (с числами) 
→ Сравнение с аналогами → Значимость → Перспективы (кратко)
```

### ⏰ Временная перспектива:
- **Прошедшее время:** что было СДЕЛАНО ("предложена и реализована...")
- **Настоящее время:** что мы ИМЕЕМ ("система обеспечивает...")
- **Акцент на РЕЗУЛЬТАТАХ:** что ПОЛУЧИЛОСЬ

### 🔑 Ключевые слова:
- "в данной работе предложена и реализована" (прошедшее!)
- "получены следующие результаты"
- "в отличие от", "по сравнению с"
- "доказано", "подтверждено экспериментально"
- "достигнуто", "обеспечено"

### ❌ Чего НЕТ:
- Мотивации проблемы (это во введении)
- Детального описания вклада (это во введении)
- Подробного описания будущей работы (это в отдельном разделе!)
- Повторения введения другими словами

---

## 🔄 СРАВНЕНИЕ НА ПРИМЕРАХ

### Пример 1: Вклад vs Результат

#### ВВЕДЕНИЕ (вклад):
```
Формализована пороговая модель восстановления зашифрованных данных 
на основе интеграции схемы Шамира и механизма социального 
восстановления в архитектуру абстрактного аккаунта экосистемы Cosmos.
```

✅ Говорит **ЧТО мы предлагаем** (общая формулировка)  
✅ Акцент на **методологии** (как подошли к проблеме)  
❌ Нет конкретных результатов

#### ЗАКЛЮЧЕНИЕ (результат):
```
В отличие от существующих решений (Argent — восстановление аккаунта, 
Pedin — восстановление активов, Leap/Keplr — централизованные 
OAuth-провайдеры), предложенная система восстанавливает зашифрованные 
пользовательские данные через децентрализованную сеть независимых 
guardians, реализованных как блокчейн-аккаунты Cosmos, без зависимости 
от Web2-сервисов.
```

✅ Говорит **ЧТО получилось** (конкретный результат)  
✅ **Прямое сравнение** с аналогами  
✅ Подчеркивает **отличия** от существующих решений

---

### Пример 2: Безопасность

#### ВВЕДЕНИЕ (вклад):
```
Проведён количественный анализ безопасности и отказоустойчивости: 
доказана конфиденциальность при компрометации до k-1 участников 
и функциональность при отказе до n-k участников для конфигурации 
(k,n)-пороговой схемы.
```

✅ Говорит **ЧТО проведено** (анализ)  
✅ Общая формулировка (для любых k и n)  
❌ Нет конкретных чисел

#### ЗАКЛЮЧЕНИЕ (результат):
```
Доказана устойчивость к компрометации до k-1 участников; для 
практической конфигурации (3,5) вероятность компрометации составляет 
менее 1% при независимой вероятности компрометации guardian p=0.1. 
Вычислительная сложность восстановления секрета через интерполяцию 
Лагранжа составляет O(k²), что приемлемо для типичных значений k ≤ 10.
```

✅ **Конкретная конфигурация:** (3,5)  
✅ **Конкретные числа:** <1%, p=0.1  
✅ **Вычислительная оценка:** O(k²)  
✅ **Практическая применимость:** k ≤ 10

### Пример 3: Реализация

#### ВВЕДЕНИЕ (вклад):
```
Реализован и экспериментально подтверждён работоспособный прототип 
на базе CosmWasm с открытым исходным кодом на локальной тестовой 
сети Cosmos SDK, демонстрирующий практическую применимость 
предложенного подхода.
```

✅ Говорит **ЧТО реализовано**  
✅ Общее описание  
❌ Нет деталей о гибкости

#### ЗАКЛЮЧЕНИЕ (результат):
```
Разработан и экспериментально подтверждён работоспособный прототип 
на базе CosmWasm с клиентским веб-интерфейсом. Открытый исходный 
код обеспечивает воспроизводимость результатов и возможность 
развертывания в различных конфигурациях Cosmos-сетей (локальных, 
корпоративных, публичных).
```

✅ **Дополнительная деталь:** веб-интерфейс  
✅ **Воспроизводимость:** открытый код  
✅ **Гибкость:** локальные/корпоративные/публичные сети  
✅ Акцент на **практической ценности**

## 📊 ТАБЛИЦА РАЗЛИЧИЙ

| Аспект | ВВЕДЕНИЕ | ЗАКЛЮЧЕНИЕ |
|--------|----------|------------|
| **Время** | Настоящее + будущее | Прошедшее + настоящее |
| **Фокус** | Что предлагаем (план) | Что получилось (результат) |
| **Детализация** | Общая формулировка | Конкретные числа |
| **Сравнения** | Краткое (другие vs мы) | Детальное (с конкретными аналогами) |
| **Проблема** | Подробно (мотивация) | Не упоминается |
| **Методология** | Общий подход | Не описывается |
| **Результаты** | Не упоминаются | Подробно (с измерениями) |
| **Вклад** | Подробно (что нового) | Кратко (в контексте результатов) |
| **Будущее** | Не упоминается | Кратко (1-2 предложения) |
| **Значимость** | Косвенно (через проблему) | Явно (почему важно) |
| **Объём** | Обычно длиннее | Обычно короче |

## 🎯 ЗОЛОТОЕ ПРАВИЛО

### ВВЕДЕНИЕ:
> "Вот **ПРОБЛЕМА**. Вот что делали **ДРУГИЕ**. Вот что мы **ПРЕДЛАГАЕМ**. Вот наш **ВКЛАД**."

**Ключ:** Убеждаем читателя, что работа **НУЖНА** и **НОВАЯ**.

### ЗАКЛЮЧЕНИЕ:
> "Мы **СДЕЛАЛИ** X. Получили **РЕЗУЛЬТАТЫ** Y. Это **ЛУЧШЕ** аналогов Z. Это **ВАЖНО** для области. **ПЕРСПЕКТИВЫ**: можно расширить на W."

**Ключ:** Показываем читателю, что работа **ВЫПОЛНЕНА** и **ЗНАЧИМА**.

## ❌ ТИПИЧНЫЕ ОШИБКИ

### Ошибка 1: Заключение = Введение другими словами
**Плохо:**
- Введение: "Предложена модель восстановления данных"
- Заключение: "В работе предложена модель восстановления данных"

**Хорошо:**
- Введение: "Предложена модель восстановления данных"
- Заключение: "Система восстанавливает данные с вероятностью успеха 99% для конфигурации (3,5)"

### Ошибка 2: Заключение слишком длинное
**Плохо:** Заключение на 2 страницы с подробным описанием будущей работы

**Хорошо:** Заключение на 0.5-1 страницу с кратким упоминанием перспектив

### Ошибка 3: Нет конкретных результатов в заключении
**Плохо:** "Система обеспечивает высокий уровень безопасности"

**Хорошо:** "Вероятность компрометации составляет менее 1% для конфигурации (3,5)"

### Ошибка 4: Введение содержит результаты
**Плохо:** "Предложена система, которая показала вероятность компрометации <1%"

**Хорошо:** "Предложена система восстановления данных на основе порогового разделения секрета"

## 📖 ИТОГОВОЕ РЕЗЮМЕ

### ВВЕДЕНИЕ = "ЧТО МЫ ХОТИМ СДЕЛАТЬ И ПОЧЕМУ"
- Мотивация (проблема важна)
- План (что предлагаем)
- Новизна (наш вклад)

### ЗАКЛЮЧЕНИЕ = "ЧТО МЫ СДЕЛАЛИ И ЧТО ПОЛУЧИЛОСЬ"
- Резюме (что сделано)
- Результаты (конкретные числа)
- Значимость (почему важно)

**Главное правило:** 
Читатель, прочитав только введение и заключение, должен понять:
1. **Зачем** эта работа нужна (введение)
2. **Что** получилось в результате (заключение)

При этом они НЕ должны дублировать друг друга!
